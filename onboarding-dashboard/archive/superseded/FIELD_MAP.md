## 3. What must not change

1. **Tab name** `Cohort Tracker May - December 26` — `getSheetByName` returns null on a rename and `getDashboardData` just `return`s, producing 16 buttons all reading "0 hires" with no error.
2. **Header on row 1, data from row 2.** One header row, no banner block.
3. **Column order A-R.** Positional. Never insert or reorder.
4. **Col H must parse to one of the 16 seeded keys.** The legal display strings are exactly: `May 11, 2026`, `May 25, 2026`, `Jun 08, 2026`, `Jun 22, 2026`, `Jul 06, 2026`, `Jul 13, 2026`, `Jul 27, 2026`, `Aug 10, 2026`, `Aug 24, 2026`, `Sep 08, 2026`, `Sep 21, 2026`, `Oct 05, 2026`, `Oct 19, 2026`, `Nov 02, 2026`, `Nov 30, 2026`, `Dec 14, 2026`. A zero-padded day is mandatory — `Sep 8, 2026` returns zero hires from every scanner while still rendering on the dashboard.
5. **Cols B, C and D are real booleans.** The STRING `"FALSE"` is truthy, and `markSlackChannelInTracker_` gates on bare truthiness (`if (!row[2])`), so a string there permanently blocks the row from ever being marked while the dashboard still shows it grey.
6. **No checkbox validation on col P.** It is dual-typed: seeded boolean `false`, then overwritten with a group URL by `markGoogleGroupInTracker_`.
7. **No apostrophes, angle brackets or double quotes** in any name, job title, location or email — every field is concatenated into the dashboard's HTML unescaped and the emails are interpolated inside single-quoted `onclick` handlers.
8. **First + last unique across all 44 rows.** The dashboard drops the second of any duplicate pair inside a cohort key.

## 5. Demo clock — which dates actually fire an automation

`dailyScanner`, `mondayScanner` and `fridayAfternoonScanner` all iterate `CONFIG.COHORT_DATES` and compare `today` against a fixed offset with an exact `===`. A branch therefore fires on exactly one calendar date per cohort and on no other date. The branches are:

| Offset | Scanner | Fires |
|---|---|---|
| `cohort-4` | `dailyScanner` | Thursday cohort notice (+ holiday alert) |
| `cohort-3` | `dailyScanner` | Friday reminder + manager DMs |
| `cohort-3` | `fridayAfternoonScanner` | Slack channel + Google group + non-US notification |
| `cohort day` | `mondayScanner` | cohort-day channel setup and manager DMs |
| `cohort+1` | `dailyScanner` | day-2 follow-up |
| `cohort+2` | `dailyScanner` | day-3 follow-up |
| `cohort+7` | `dailyScanner` | week-1 check-in |
| `cohort+9` | `dailyScanner` | week-2 check-in |

> **The pinned demo date 2026-09-11 fires nothing.** It is `cohort+3` relative to 2026-09-08 and there is no `+3` branch; the cohort dates implied by the branches above (2026-09-02, 2026-09-04, 2026-09-09, 2026-09-10, 2026-09-11, 2026-09-14, 2026-09-15) are none of the 16 `COHORT_DATES`. ### 5b. Cohorts whose Friday work can never run (pre-existing `Code.gs` weakness, NOT a data fault)

`dailyScanner` derives the Thursday notice and the Friday setup from FIXED offsets — `thursdayDate = addDays_(cohort, -4)` and `fridayDate = addDays_(cohort, -3)` (Code.gs:1268-1270) — while `fridayAfternoonScanner` is trigger-bound to **Fridays 12 PM PT** (Code.gs:2419-2424) *and* additionally gates on `today !== addDays_(cohortDate, -3)`. For any cohort that does not fall on a Monday the two can never coincide, so that cohort gets no Slack channel, no Google group and no `notifyNonUSHires_` call.

| Cohort | Weekday | `cohort-3` resolves to | Weekday | Hires in this workbook |
|---|---|---|---|---|
| `2026-09-08` | Tue | `2026-09-05` | **Sat** | 4 |

The 2026-09-08 cohort is the live one: it is a Tuesday because Labor Day (`2026-09-07`, present in `CONFIG.US_HOLIDAYS_2026`) shifted it, but `isUSHoliday_("2026-09-08")` is **false** — the holiday date itself is in the list, the shifted cohort date is not — so the holiday branch at Code.gs:1275 never fires either. Fix belongs in `Code.gs`: derive Thursday/Friday from the preceding weekday instead of a fixed -4/-3, or add a holiday-shift exceptions map. Do **not** move the cohort date — `CONFIG.COHORT_DATES` is a fixed literal.

Only the unconditional tail of `fridayAfternoonScanner` (`checkGmailForHRReport` plus the +4h/+8h retry triggers) runs on a date with no matching branch, so an untimed demo shows Gmail polling and nothing else. Note `fridayAfternoonScanner` is also the only caller of `notifyNonUSHires_` (Code.gs:2116) and only ever at `cohort-3`: a **past** cohort can never raise a non-US alert, whatever its locations say.
